## 1. 產品目標

**一句話**：免費、免註冊、資料預設只存在自己裝置上的繁中 TOEIC 自學工具，**閱讀與單字**達到付費產品的品質。

**目標使用者**：繁體中文使用者，TOEIC L&R 約 600–850 分，目標 900 以上。

**「商業級」在定位 A 的意思**：以評估報告的九個面向為準，和閱讀、單字有關的面向要達到 7 分（一般付費 App 的水準）。聽力在音檔完成前維持「裝置語音、非商業級」並在畫面上明確標示。

| 面向 | 現況 | 本規格目標 | 達成版本 | 達標的具體條件 |
|---|---:|---:|---|---|

**範圍**：§4 列出的 v1.3–v1.7 共五個版本；v1.8 以後只寫大綱。

- React／TypeScript 重寫、建置工具（bundler）。

## 4A. 10/31 考前衝刺計畫（2026-10-09 起，優先於 §4）

使用者的下一次考試是 **2026-10-31**，只剩 22 天，每天約 1 小時，總共大約 22 小時的練習時間。所以這段期間只做「考前用得上、而且能在 10/26 前完成」的項目；其他項目延到考試之後。

**這段時間最有效的是什麼**（決定優先順序的依據）：
- 熟悉新制題型：聊天訊息與意圖題、插入句子位置題、5 題的多篇題組、圖表題、三人對話。題庫目前缺少這些題型，考場上第一次看到會浪費時間。
- 時間分配與耐力：Part 7 能不能寫完，常常決定 850 和 900。所以要練完整的 75 分鐘閱讀測驗。
- 補上系統性的文法或字彙漏洞：從錯題本和類別正確率找出來。
- 大量背新單字在 3 週內效果有限，只維持每天的到期複習。

**延到考試之後**：FSRS、完整技能標籤與掌握度、AI 變體題、帳號登入（v1.5）、Service Worker 等工程地基（v1.4 原規劃中的大部分）、神經語音音檔、Part 1。

**題目資料格式**：衝刺期不重構資料格式（避免影響現有錯題本與紀錄）。新題沿用現有陣列格式，加在內建題目的尾端（INV-07）；可以選擇性加上 `src`（來源批次）、`lvl`（編輯估計難度）、`skill`（技能）欄位。完整測驗另存一個資料檔，錯題本使用獨立的鍵。

**新題的品質流程**（D-A11）：
1. Claude 撰寫，每題附答案根據與錯誤選項的錯因（寫在解析裡）。
2. 自動檢查：沿用 `content-audit/scripts/lint.mjs`，加上 Part 2 選項長度檢查。
3. 兩次獨立盲解：由兩個獨立的審查代理分別作答，看不到答案鍵，並回報有沒有第二個可接受答案。兩次都和答案鍵一致、都沒回報兩可，才通過；否則修改後重跑，或丟棄。
4. 使用者抽檢：每批隨機抽 5%（每批至少 10 題），加上任何被標記的題目。抽檢中如果有 1 題答案錯，或有 2 題以上有問題，整批退回重新檢查。
5. 上線後：AI 解析的判定與「這題有問題」回報進入待審清單，下一次發布時修正。

**外部測驗成績**（D-A12）：使用者會用網路上的資源，不買官方試題書。App 不收錄任何外部題目。網路上流傳的「全真試題」很多是盜版的官方書，App 只提供記錄成績的功能（來源、日期、聽力與閱讀的原始答對數或分數），一律標示為未校準。ETS 與台灣多益官網提供的官方範例題可以用來熟悉題型。真正有校準的測量是 10/31 的考試本身。

## 5. 需求

格式：每條需求有 ID、說明和驗收標準。驗證案例與方法見 [verification.md](verification.md)，用相同的需求 ID 對應。

### 5.1 v1.3.0 止血

**MET-01 移除未校準的 TOEIC 分數**
- 刪除把正確率換算成 L/R 分數的函式與所有呼叫處：首頁、統計頁、模擬考報告、模擬考歷史與趨勢圖。
- 所有介面文字中不再出現「預估分數」「預估總分」「粗估」，包括「我的」頁面的卡片說明。
- 改為顯示練習答對率，一律附上「答對題數／作答題數」。
- 首頁與統計頁加一行說明：答對率只反映本工具內的練習，不是 TOEIC 分數。
- 驗收：在原始碼與所有畫面中搜尋上述字詞，結果為 0；畫面不出現 10–990 範圍的分數。

**MET-02 一致的答對率算法**
- 聽力與閱讀用同一套規則計算：**計入**一般練習（Part 2、3/4、5、6、7）與模擬考的作答；**不計入**錯題本重考（那些是做過的題，會墊高答對率）。
- 目前程式在錯題本重考時會更新聽力統計、不會更新閱讀統計；改為兩者都不更新。錯題本自己的掌握進度（連續答對次數）不受影響。
- 樣本門檻維持聽力 15 題、閱讀 20 題。未達門檻時顯示「再答 N 題後顯示」，不只顯示「—」。
- 驗收：單元測試確認錯題本重考前後，聽力與閱讀的累計數字都不變；一般練習與模擬考會增加。

**MET-03 連續天數與熱圖涵蓋所有學習活動**
- 只做錯題本重考或只完成模擬考的那天，也算有學習；計入連續天數與 14 天熱圖。
- 每日紀錄的欄位補齊時不可呼叫 `save()`（INV-01）。
- 驗收：單元測試中，某天只有錯題本重考 3 題，連續天數為 1；只完成一次模擬考亦同。

**MET-04 模擬考報告與趨勢圖**
- 交卷報告分開顯示聽力與閱讀的答對率和題數，不把兩節合成一個總分。
- 趨勢圖縱軸固定為 0–100%，聽力與閱讀各一條線；不再依最高、最低值自動縮放。
- 舊版歷史紀錄：有原始題數的，改以答對率顯示並畫進趨勢圖；沒有原始題數的，標示「舊版紀錄，無法比較」，不畫進趨勢圖。舊紀錄原樣保留，不刪除也不改寫。
- 驗收：三種格式的歷史紀錄（無題數、v1.1 格式、新格式）都正確顯示；趨勢圖的點位與答對率一致。

**MET-05 結算文案**
- 單輪全對時，不再說「900+ 的水準」「閱讀力已達高分水準」這類能力判定；改為鼓勵用新題確認。
- 驗收：搜尋原始碼，沒有以單輪結果判定程度的文字。

**AUD-01 語音就緒偵測**

- 雲端同步改為登入 Google 帳號後使用。不登入時，App 所有功能照常可用，資料只存在本機。
- 登入畫面說明會上傳哪些資料、存在哪裡、如何刪除。

**ACC-02 帳號範圍的資料規則**
- 新路徑 `users/$uid`：只有 `auth.uid === $uid` 能讀寫；沿用 SEC-01 的結構驗證。
- 驗收：模擬器測試中，未登入與他人帳號的讀寫全部被拒絕。

**ACC-03 舊同步代碼搬移**
- 已設定同步代碼的使用者登入後，提示「把代碼中的進度搬到帳號」。搬移流程：讀取 `sync/<code>` → 與本機比較 → 寫入 `users/<uid>` → 確認寫入成功 → 刪除 `sync/<code>` → 清除本機代碼。
- 任一步失敗，原資料保持不變並可重試。
- 停用時程依 O-04。
- 驗收：模擬器中完成搬移，前後資料逐欄位相同；在每一步注入失敗，原資料都未被改動。

**ACC-04 刪除資料**
- 「設定」頁提供三個分開的操作：登出、刪除雲端資料、刪除本機資料。每個操作的確認畫面清楚列出影響範圍。
- 驗收：每個操作只影響它說明的範圍。

**ACC-05 隱私權政策與使用條款**
- App 內頁面與 repo 中的 `PRIVACY.md`、`TERMS.md`：資料存放位置、沒有分析追蹤、刪除方式、聯絡方式（O-05）、同步是「最後寫入者覆蓋」的限制。
- 商標聲明：TOEIC 是 ETS 的註冊商標，本產品與 ETS 無關、未經 ETS 認可；不保證分數。
- 驗收：頁面從「我的」可以找到；內容與實際行為一致（人工比對）。

### 5.4 v1.6.0 閱讀內容

**CNT-01 審題工具**
- 獨立頁面 `tools/review.html`，不出現在 App 導覽中，直接用瀏覽器開啟。
- 一次一題。**答案、證據、解析在使用者作答前完全隱藏**；作答後才顯示正解、答案證據、解析和每個干擾項的錯因。
- 判定三選一：「同意」、「有疑問」（必填原因）、「退回」（必填原因）。另有勾選清單：唯一正解、英文自然、解析正確、干擾項合理、看不出抄自官方或出版題目。
- 支援鍵盤操作、顯示進度、可中斷後繼續（進度存在瀏覽器）。
- 結果匯出成 JSON 檔，由 Claude 合併進題目的 `reviewRecords`。
- 驗收：審題途中重新整理不會遺失進度；作答前在 DOM 中找不到答案文字；匯出的紀錄包含題目 ID、版本、使用者答案、判定、原因、時間。

**CNT-02 題目建置流程**
- 閱讀卷 R1、R2 的題目（每卷 Part 5 30 題、Part 6 4 篇 16 題、Part 7 單篇 29 題與多篇 25 題）由 Claude 全新撰寫，草稿放在 `content/drafts/`，一行一題的 JSON。
- 每題欄位：穩定 ID、版本、Part、題幹、選項（每個選項有 ID）、正解選項 ID、答案證據（指出原文句子或文法規則）、繁中解析、每個錯誤選項的錯因、技能標籤、編輯估計難度與理由、來源（作者、撰寫日期、撰寫方式）、權利狀態、審核紀錄。Part 6／7 的文章另存一份，題目以文章 ID 引用。
- `tools/build-content.mjs` 只輸出同時符合以下條件的題目：AI 作者自查完成、使用者判定「同意」、來源與權利已記錄、通過 lint。輸出到 `js/data/reading-reviewed.js`。
- 使用者判定「有疑問」或「退回」的題目：修改後版本號加 1、重新審題；不能直接改狀態。
- 權利處理：AI 原創題由使用者在審題時確認「看不出抄自官方或出版題目」，另由 Claude 對 10% 抽樣題目的特殊句子做網路搜尋比對，結果記錄在題目的來源欄位。
- 驗收：未經審核的題目不會出現在輸出檔；lint 失敗時建置以非 0 結束碼結束。

**CNT-03 新格式題目的執行支援**
- 新題目使用穩定 ID（例如 `R1-P5-001`）。錯題本、出題紀錄都以 ID 為鍵；舊題目維持原本的陣列索引鍵，兩者不衝突。
- 選項洗牌以選項 ID 為準，不依賴顯示順序。
- 驗收：新舊題目混合練習時，錯題本、輪替、統計都正確；舊使用者的資料升級後沒有遺失。

**CNT-04 干擾項回饋**
- 新格式題目答錯時，顯示「你選的選項為什麼不對」（該選項的錯因）以及答案證據；答對時顯示答案證據和解析。
- 舊題目沿用原本的詳解。
- 驗收：每個新格式題目選每一個錯誤選項，都顯示對應的錯因。

**CNT-05 完整閱讀測驗**
- 閱讀卷 R1、R2 各一份：Part 5 30 題、Part 6 16 題、Part 7 54 題，共 100 題，限時 75 分鐘。
- 可標記、跳題、修改答案；時間到自動交卷一次。
- 每作答一題就存檔。計時以開始時間為準，重新整理或關閉分頁後回來可以繼續，時間不會暫停或重設。
- 報告：分 Part 與技能的原始答對數、答對率、未作答數、用時。標示「藍圖一致練習卷（未校準）」，不顯示 TOEIC 分數。
- 驗收：題數與配置完全符合藍圖；計時邊界（剩 1 秒作答、時間到、重新整理）全部正確；全對、全錯、全空白的報告沒有除以零或 NaN。

**CNT-06 依技能加權**

- 驗收：單元測試涵蓋門檻邊界（4 題、5 題、84%、85%）。

**CNT-07 題目回報**

**CNT-08 舊題庫來源紀錄**

### 5.7 AI 輔助的後續階段（大綱，各階段開工前再寫成詳細需求）

**第二階段：記憶強化（排在 v1.4 之後）**
- AI-10 錯題變體題：錯題本排到複習時，可以選擇「換一題同觀念的新題」，由 AI 依原題的文法點或技能產生新句子。變體題只用在錯題本複習，**不計入練習答對率、弱項統計與錯題本的移除次數**（移除仍要原題連續答對 2 次、跨天）。每題變體在顯示前先由第二次呼叫盲解，結果不一致就丟棄。
- AI-11 單字新例句：單字卡翻面後可以要求「換一個例句」，避免只記得同一個句子。例句必須包含該單字或其變化形（程式檢查）。
- AI-12 每週弱項摘要：把各類別答對率、錯題本內容整理成數字後送出（不送作答歷史原文），由 AI 寫出下週的練習重點。

**第三階段：題庫生成（與 v1.6 的 CNT-02 題目建置流程合併）**
- AI-20 生成：一次生成一批，指定 Part、技能、難度，並刻意補上現有題庫缺的題型（意圖題、圖表題、三人對話、插入句子位置題、聊天類文件）。輸出直接採用 CNT-02 的新格式（含證據、干擾項錯因、技能標籤）。
- AI-21 自動篩選：依序通過 (1) 內容 lint（ENG-02），(2) Part 2 選項長度檢查（正解不可經常是最長的選項），(3) 另一次呼叫的盲解：看不到答案作答，並回報有沒有第二個可接受答案。盲解答案不一致或回報兩可，就淘汰。盲解優先使用和生成不同的模型。
- AI-22 使用者審核：通過篩選的題目進入審題工具（CNT-01）的待審區，使用者判定「同意」才進正式題庫。**AI 不能核准 AI 寫的題目**（verification.md 原則 6）。
- AI-23 未審練習區（選用）：使用者可以開啟「即時生成新題練習」，題目標示「AI 新題・未審」、附「回報有誤」按鈕，不計入任何統計與錯題本。
- 生成作業在使用者的電腦上用腳本執行（同樣使用自帶金鑰），不在 App 內批次生成。

## 6. 不變條件（每個版本都必須維持）

| ID | 條件 | 理由 |
|---|---|---|
| INV-01 | 開機流程和 `renderers.home()` 路徑上不可呼叫 `save()` | 會搶在雲端比對前改掉時間戳，蓋掉真實進度（2026-07-09 的事故） |
| INV-02 | 會成為 Firebase key 的字串不可含 `. # $ / [ ]` | 會讓整份同步靜默失敗（2026-07-11 的事故） |
| INV-03 | 任何版本都能讀入 v1.0–v1.1 的本機資料和備份檔，不遺失欄位 | 使用者資料不可回復 |
| INV-04 | 不顯示未校準的 TOEIC 分數 | MET-01 的誠實原則 |
| INV-05 | 所有動態內容經過 `esc()`，包含 HTML 屬性中的值 | 2026-07-12 的 XSS 事故 |
| INV-06 | 解析不引用 (A)(B)(C) 字母 | 選項會洗牌 |
| INV-07 | 自訂題庫附加在內建陣列尾端，舊索引不變 | 錯題本與完成紀錄以索引為鍵 |
| INV-08 | 不加入任何遙測、分析或第三方追蹤 | 定位 A 的隱私承諾 |
| INV-09 | 物件中要寫進 Firebase 的數值欄位不可為 `null` 或省略 | Firebase 會刪除只有 null 值的節點（錯題本 `n` 欄位） |
| INV-10 | API 金鑰只存在本機（預設 `sessionStorage` 的 `toeic900_ai_key`，勾選「記住」才存 `localStorage` 的 `toeic900_ai`），不進 `S`、不同步、不進備份、不出現在任何紀錄或匯出檔 | 金鑰外洩會被盜用、產生費用 |
| INV-11 | AI 請求只在使用者按下按鈕後送出；沒有金鑰時不發出任何 AI 請求 | 定位 A 的隱私承諾（INV-08）與費用控制；AI 請求是使用者主動送出的題目內容，不是遙測 |
| INV-12 | AI 的輸出不會自動改變計分、錯題本或題庫；未經使用者審核的 AI 題目不計入任何統計 | 題庫審查顯示 AI 寫的題目約 2% 有問題（2026-10-07 題庫審查報告） |

## 7. 風險

| 風險 | 影響 | 處理 |
|---|---|---|
| 審題工作量 | 閱讀卷 R1、R2 共 200 題約需 7–10 小時（每題 2–3 分鐘）；達到 1,200 題需 40–60 小時 | 分批審；v1.6 只要求 200 題；審題工具支援中斷後繼續 |
| 審題者也是目標學習者 | 看不出問題不代表沒有問題 | 對外宣稱商業品質前，請英語教師抽樣複查高難度題 |
| Service Worker 讓使用者卡在舊版 | 修正無法送達 | 版本化快取、更新提示、緊急停用版本（ENG-05） |
| 登入需要 Firebase 主控台設定 | v1.5 無法完成 | O-03 提早確認；未完成前維持同步代碼 |
| 程式作者與驗收者都是 AI | 獨立性不足 | 每版由獨立的審查代理做程式審查，加上使用者真機驗收與部署核准（見 verification.md §1） |
| 共用資料夾同時有兩個代理 | 檔案寫到錯的分支 | D-A06：Claude 只在本 worktree 工作 |
| AI 解析本身有錯 | 學到錯誤觀念 | 畫面標示「AI 產生，可能有誤」；題庫原有解析永遠顯示在上方；AI 判定題目有誤時只記錄、不改計分（INV-12） |
| 瀏覽器中的 API 金鑰被讀取 | 金鑰被盜用產生費用 | 只供本人使用（D-A08）；建議在 Anthropic 主控台設定每月上限；可隨時刪除金鑰並在主控台撤銷 |
| Anthropic API 規格、模型名稱或價格變動 | 功能失效或費用增加 | 模型名稱集中在一個常數；錯誤訊息顯示 API 回傳的原因；在設定頁可以換模型 |
